  ## 0. Инструкция для ИИ-агента: как пользоваться документом
  
  1. **Читай документ целиком перед началом любой фазы.** Разделы 6–9 (стек, архитектура, ключевые решения, модель данных) обязательны к соблюдению; отступления допускаются только с записью причины в `docs/DECISIONS.md` (формат ADR).
  2. **Работай строго по фазам из раздела 16.** Не переходи к следующей фазе, пока не выполнены критерии приёмки (Definition of Done) текущей.
  3. **Веди файл `docs/PROGRESS.md`:** для каждой фазы — статус (`todo / in progress / done`), список сделанного, известные проблемы, дата.
  4. **Каждый коммит** — атомарный, в формате Conventional Commits: `feat(blocker): ...`, `fix(detector): ...`, `test(session): ...`, `chore(build): ...`. В теле коммита ссылайся на ID требований (`FR-21`, `TR-05`).
  5. **Перед завершением любой задачи** обязательно выполняй и добивайся зелёного результата:
     ```bash
     ./gradlew :app:assembleDebug
     ./gradlew testDebugUnitTest
     ./gradlew lintDebug detekt
     ```
  6. **Не выдумывай API.** Если не уверен в сигнатуре Android API / библиотеки — сверяйся с официальной документацией (developer.android.com) и исходниками библиотек. **Все версии зависимостей зафиксированы в §6 и `gradle/libs.versions.toml` на весь срок разработки v1.0 — менять их запрещено** (см. §6.1). Новые артефакты подключать только через ADR в `docs/DECISIONS.md`.
  7. **Никаких заглушек в релизных путях.** `TODO()` и `NotImplementedError` допустимы только внутри фазы, в которой над ними ведётся работа, и должны быть закрыты до её завершения.
  8. **Приватность по умолчанию:** приложение не имеет разрешения `INTERNET` (см. NFR-10). Любое добавление сетевого кода — запрещено без явного изменения ТЗ.
  9. **Требования к коду:** Kotlin, идиоматичный стиль, без Java. Публичные классы и неочевидные решения — с KDoc. Строки UI — только в ресурсах (`strings.xml`, ru + en).
  10. Если требование противоречит ограничениям платформы (например, изменилась политика Android), **не обходи ограничение хаками** — зафиксируй проблему в `PROGRESS.md`, предложи альтернативу и реализуй наиболее близкое допустимое поведение.
  11. Не запускай параллельных субагентов.

  ## 1. Общее описание продукта
  
  **Название:** Focus
  **Package name:** `app.focus.android` (изменяемо при публикации)
  **Платформа:** Android, `minSdk = 26` (Android 8.0), `compileSdk = 37`, `targetSdk = 36` (Android 16). Версии toolchain и библиотек — **§6 (LOCKED до релиза 1.0.0)**.
  **Тип:** offline-приложение цифрового благополучия (digital wellbeing).
  
  ### 1.1. Суть
  Пользователь выбирает приложения-«отвлекатели» (соцсети, игры, мессенджеры). Focus в течение активной **сессии фокуса** отслеживает, какое приложение находится на переднем плане, и при запуске заблокированного приложения мгновенно перекрывает его полноэкранным **экраном блокировки**. Существуют два режима строгости:
  
  - **Soft Lock (мягкая блокировка)** — экран блокировки можно пройти, но с «трением»: задержка-обратный отсчёт, дыхательная пауза, ввод причины, ограниченное число пропусков, ограниченное время «окна» доступа.
  - **Hard Lock (жёсткая блокировка)** — экран блокировки пройти нельзя до конца сессии. Приложение защищено от попыток отключения/удаления на время сессии в рамках возможностей платформы.
  
  ### 1.2. Ценности продукта
  - Мгновенная реакция (< 300 мс от открытия приложения до появления блокировки).
  - Надёжность: сессия переживает перезагрузку, убийство процесса, смену пользователя настроек.
  - Полная приватность: без интернета, без аналитики, все данные на устройстве.
  - Современный, спокойный, минималистичный интерфейс (Material 3, динамические цвета, тёмная тема).
  
  ### 1.3. Вне рамок (Out of scope v1.0)
  - Блокировка сайтов в браузере (URL-фильтрация).
  - Синхронизация между устройствами, аккаунты, облако.
  - Родительский контроль / управление чужим устройством.
  - Монетизация, реклама, подписки.
  - Wear OS, планшетный layout как отдельный дизайн (адаптивность базовая — обязательна, см. NFR-07).

  ## 2. Термины
  
  | Термин | Определение |
  |---|---|
  | **Целевое приложение (Target app)** | Приложение из списка блокируемых. |
  | **Профиль (Profile)** | Именованный набор целевых приложений + настройки режима (soft/hard) и параметров трения. Например «Работа», «Сон», «Учёба». |
  | **Сессия (Session)** | Интервал времени, в течение которого активен профиль. Имеет начало, длительность/конец, режим блокировки, состояние. |
  | **Расписание (Schedule)** | Правило автоматического запуска сессии: дни недели + время начала/конца + профиль. |
  | **Экран блокировки (Block Screen / Blocker)** | Полноэкранный UI, перекрывающий целевое приложение. |
  | **Детектор (Detector)** | Компонент, определяющий текущее foreground-приложение. |
  | **Пропуск (Bypass)** | Разрешённый проход через soft lock в целевое приложение на ограниченное время (окно доступа). |
  | **Окно доступа (Access window)** | Время, на которое целевое приложение разблокируется после пропуска (например 5 минут). |
  | **Белый список (Allowlist)** | Приложения, которые никогда не блокируются (лаунчер, звонилка, SystemUI, сам Focus и т. д.). |
  | **Строгий режим (Strict / Tamper protection)** | Набор мер в hard lock, затрудняющих отключение Focus во время сессии. |

  ## 3. Целевая аудитория и пользовательские сценарии
  
  ### 3.1. Аудитория
  Люди 16–45 лет, желающие сократить бесконтрольное использование смартфона: студенты, удалённые работники, люди с проблемами концентрации (в т. ч. ADHD), те, кто хочет не пользоваться телефоном перед сном.
  
  ### 3.2. Ключевые user stories
  
  - **US-01.** Как пользователь, я хочу за 2 минуты после установки выбрать 3–5 приложений и запустить первую сессию на 25 минут.
  - **US-02.** Как пользователь, я хочу, чтобы при открытии Instagram во время сессии я мгновенно видел экран с напоминанием о цели и кнопкой «Вернуться».
  - **US-03.** Как пользователь soft lock, я хочу иметь возможность всё же зайти в приложение по необходимости, но после 30-секундной паузы и указания причины — и чтобы таких пропусков было не более 3 за сессию.
  - **US-04.** Как пользователь hard lock, я хочу, чтобы обойти блокировку было невозможно ни через настройки, ни через удаление, ни через перезагрузку, пока не истечёт таймер.
  - **US-05.** Как пользователь, я хочу настроить расписание «Пн–Пт 09:00–13:00 → профиль “Работа”, hard lock» и не думать об этом каждый день.
  - **US-06.** Как пользователь, я хочу видеть статистику: сколько раз я пытался открыть заблокированные приложения, сколько сессий завершил, сколько времени сфокусирован.
  - **US-07.** Как пользователь, я хочу запускать/останавливать сессию из виджета на рабочем столе или из шторки быстрых настроек.
  - **US-08.** Как пользователь, я хочу, чтобы экстренный вызов и звонилка были доступны всегда.
  - **US-09.** Как пользователь, я хочу, чтобы при hard lock существовал заранее настроенный «аварийный выход» (например, ожидание 24 часов или ввод длинного текста), либо возможность полностью его отключить в настройках профиля.
  - **US-10.** Как пользователь, я хочу помодоро-режим: 25 мин фокуса / 5 мин перерыв × N циклов, во время перерыва блокировка снимается.

  ## 4. Функциональные требования
  
  ### 4.1. Онбординг и выдача разрешений
  
  - **FR-01.** При первом запуске показывается онбординг из 3–4 экранов: ценность продукта → выбор приложений → выдача разрешений → создание первого профиля.
  - **FR-02.** Экран разрешений отображает **чек-лист** с актуальным статусом каждого разрешения (получено / не получено), кнопкой перехода в соответствующие системные настройки и понятным объяснением, зачем оно нужно. Разрешения:
    1. **Доступ к статистике использования** (`PACKAGE_USAGE_STATS`) — обязательное (детекция, fallback).
    2. **Служба специальных возможностей** (`AccessibilityService`) — рекомендуемое (мгновенная детекция + действия «Домой»).
    3. **Показ поверх других приложений** (`SYSTEM_ALERT_WINDOW`) — обязательное (запуск экрана блокировки из фона).
    4. **Уведомления** (`POST_NOTIFICATIONS`, Android 13+) — рекомендуемое (уведомление о сессии).
    5. **Игнорирование оптимизации батареи** (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) — рекомендуемое.
    6. **Точные будильники** (`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`) — для расписаний и точного завершения сессии.
    7. **Администратор устройства** (Device Admin) — опциональное, только для строгого режима hard lock (защита от удаления).
  - **FR-03.** Статус разрешений пересчитывается при каждом `onResume` главного экрана и при возврате из системных настроек. Без обязательных разрешений запуск сессии невозможен: кнопка «Старт» ведёт на экран разрешений.
  - **FR-04.** Для Android 13+ при отсутствии разрешения Accessibility у side-loaded приложения (ограничение «Restricted settings») показывается пошаговая инструкция с иллюстрацией, как разрешить.
  - **FR-05.** Онбординг можно пропустить (кроме обязательных разрешений при первом запуске сессии) и повторно открыть из настроек.
  
  ### 4.2. Список приложений и профили
  
  - **FR-10.** Экран выбора приложений показывает все установленные приложения с лаунчер-иконкой (`Intent.CATEGORY_LAUNCHER`), с иконкой, названием, поиском, сортировкой (по алфавиту / по времени использования за 7 дней), фильтром «уже выбранные». Системные приложения — в отдельной сворачиваемой секции.
  - **FR-11.** Приложения из **белого списка по умолчанию** (см. FR-60) нельзя выбрать для блокировки; они отображаются серым с пояснением.
  - **FR-12.** Пользователь может создавать неограниченное число **профилей**. Профиль содержит: имя, иконку/эмодзи, цвет, список целевых приложений, режим (Soft / Hard), параметры Soft Lock (раздел 4.4), параметры Hard Lock (раздел 4.5), длительность по умолчанию, флаг «блокировать уведомления целевых приложений» (см. FR-16).
  - **FR-13.** Предустановленные шаблоны профилей при первом запуске: «Глубокая работа» (soft, 50 мин), «Сон» (hard, до 07:00), «Детокс» (hard, 2 ч). Шаблоны редактируемы и удаляемы.
  - **FR-14.** Изменение состава целевых приложений профиля **во время активной сессии hard lock запрещено** (кнопки неактивны с пояснением). В soft lock — разрешено добавлять, но не удалять приложения.
  - **FR-15.** При установке нового приложения во время активной сессии (`ACTION_PACKAGE_ADDED`) показывается уведомление с предложением добавить его в текущий профиль (в hard lock — добавляется автоматически, если включена опция «Блокировать новые приложения»).
  - **FR-16.** (Опционально, если получен доступ Notification Listener) — скрытие уведомлений целевых приложений во время сессии. **В v1.0 реализуется как отключаемая опция, по умолчанию выключена.** Требует `BIND_NOTIFICATION_LISTENER_SERVICE`. Если разрешение не выдано — опция скрыта.
  
  ### 4.3. Сессии
  
  - **FR-20.** Сессия запускается: вручную (кнопка «Старт» с выбором профиля и длительности), по расписанию (FR-40), из виджета/тайла (FR-70), через помодоро (FR-27).
  - **FR-21.** Длительность: пресеты 15/25/45/60/90/120 мин, произвольная (от 1 мин до 24 ч), «до времени» (time picker), «бесконечно» (только Soft Lock — завершается вручную).
  - **FR-22.** Одновременно может быть активна **только одна сессия**. Попытка запустить вторую предлагает заменить текущую (в hard lock — запрещено).
  - **FR-23.** Состояния сессии: `SCHEDULED → RUNNING → (PAUSED) → COMPLETED | CANCELLED | EXPIRED`. Пауза доступна только в Soft Lock (макс. 3 паузы, макс. 10 минут каждая — настраиваемо).
  - **FR-24.** Сессия **персистентна**: хранится в БД с абсолютным временем окончания (`endAtEpochMillis`). После перезагрузки устройства, обновления приложения или убийства процесса сессия восстанавливается и продолжается (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, перезапуск foreground service).
  - **FR-25.** Во время сессии показывается постоянное (ongoing) уведомление с: названием профиля, оставшимся временем (обновление не чаще 1 раз/мин, с использованием `setChronometer`/`setUsesChronometer` для отсчёта), количеством заблокированных попыток, кнопками «Открыть Focus», «Завершить» (только Soft Lock).
  - **FR-26.** По завершении сессии — уведомление и экран итогов: длительность, число попыток открыть целевые приложения, число пропусков, серия (streak) дней с завершёнными сессиями.
  - **FR-27.** Помодоро-режим: параметры «фокус» (по умолчанию 25 мин), «короткий перерыв» (5), «длинный перерыв» (15), «циклов до длинного перерыва» (4), «всего циклов» (1–12). В перерыве блокировка выключена, уведомление сообщает о перерыве, за 30 с до окончания перерыва — предупреждение. Режим строгости помодоро — тот же, что и у профиля.
  - **FR-28.** Отмена сессии: Soft Lock — кнопкой «Завершить» с подтверждением; Hard Lock — только через «аварийный выход» (FR-35), если он включён в профиле.
  
  ### 4.4. Soft Lock (мягкая блокировка)
  
  - **FR-30.** При открытии целевого приложения появляется экран блокировки (раздел 4.6) с кнопками «Вернуться к делу» (уводит на Home) и «Мне правда нужно» (запуск процедуры пропуска).
  - **FR-31.** Процедура пропуска (настраивается в профиле, любые комбинации):
    - **Задержка**: обратный отсчёт 10 / 30 / 60 / 120 с (по умолчанию 30). Кнопка подтверждения появляется только после его окончания. Если пользователь ушёл с экрана — отсчёт сбрасывается.
    - **Дыхательное упражнение**: анимация «вдох 4 с — задержка 4 с — выдох 6 с» × 3 цикла (вместо/вместе с отсчётом).
    - **Причина**: обязательный ввод текста (мин. 10 символов), сохраняется в статистике.
    - **Ввод фразы**: набрать заданную фразу (по умолчанию «Я осознанно отвлекаюсь от своей цели»), без автозаполнения/вставки.
  - **FR-32.** После пропуска целевое приложение доступно на время **окна доступа** (1 / 3 / 5 / 10 / 15 мин, по умолчанию 5). В уведомлении виден таймер окна. За 30 с до конца — ненавязчивый toast/уведомление. По истечении — блокировка возобновляется, при нахождении в целевом приложении экран блокировки показывается немедленно.
  - **FR-33.** Лимит пропусков за сессию: 0 (= фактически hard lock без защиты) / 1 / 3 / 5 / без лимита (по умолчанию 3). При исчерпании — кнопка «Мне правда нужно» скрыта, отображается «Пропуски исчерпаны».
  - **FR-34.** Пропуск действует только для одного приложения (того, что пытались открыть). Опция профиля «пропуск открывает все приложения профиля» — по умолчанию выключена.
  
  ### 4.5. Hard Lock (жёсткая блокировка) и защита от обхода
  
  - **FR-35.** В Hard Lock экран блокировки не содержит кнопки пропуска. Единственная кнопка — «Вернуться к делу» (Home). **Аварийный выход** (настраивается при создании профиля, изменить во время сессии нельзя):
    - «Отключён» (по умолчанию для профиля «Сон»),
    - «Задержка 10 мин» — запрос отмены, сессия завершится через 10 минут ожидания, если запрос не отозван,
    - «Перепечатать текст» — набрать 300 символов случайно сгенерированного текста без ошибок,
    - «Доверенный контакт» — (v1.1, вне рамок).
  - **FR-36.** На время сессии hard lock **в список блокировки автоматически добавляются**:
    - системное приложение «Настройки» (`com.android.settings` и vendor-варианты, определяются через `Intent(Settings.ACTION_SETTINGS)` resolve),
    - установщики/маркеты (`com.android.vending`, `com.android.packageinstaller`, `com.google.android.packageinstaller`),
    - экран «О приложении» Focus (перехватывается по `ACTION_APPLICATION_DETAILS_SETTINGS`, т. к. он открывается в пакете Settings),
    - другие лаунчеры, кроме текущего дефолтного (защита от смены лаунчера),
    - приложения-«убийцы задач», известные по списку.
    Пользователь может **добавить исключения** для настроек заранее в профиле (например, разрешить Wi‑Fi настройки — реализуется путём разрешения конкретных Activity через deep link из Focus: экран «Разрешённые настройки» с кнопками «Wi‑Fi», «Bluetooth», «Звук», которые открывают соответствующие `Settings.ACTION_*` и временно (60 с) снимают блокировку с пакета Settings).
  - **FR-37.** Если пользователь всё же попадает в Настройки → Специальные возможности или Настройки → Focus, детектор (при активном Accessibility) выполняет `GLOBAL_ACTION_BACK`/`GLOBAL_ACTION_HOME` и показывает экран блокировки с текстом «Настройки недоступны во время сессии».
  - **FR-38.** **Device Admin (опционально, включается в настройках профиля «Защита от удаления»)**: при активации `DeviceAdminReceiver` приложение нельзя удалить, не отключив администратора, а раздел настроек для отключения — заблокирован (FR-36). При запросе отключения администратора (`onDisableRequested`) возвращается предупреждающий текст. Вне сессии администратор отключается самим приложением по кнопке в настройках.
  - **FR-39.** При перезагрузке в hard lock сессия восстанавливается в течение ≤ 10 с после `BOOT_COMPLETED` (в т. ч. `LOCKED_BOOT_COMPLETED` с `directBootAware` для сервиса и хранилища состояния сессии — device-protected storage).
  - **FR-39a.** Ограничения, которые **невозможно** обойти на непривилегированном Android, документируются в экране «Как работает защита» честно: безопасный режим, ADB, сброс к заводским настройкам, отключение через второго пользователя. Приложение не должно вводить в заблуждение.
  
  ### 4.6. Экран блокировки
  
  - **FR-50.** Полноэкранный, edge-to-edge, без status/navigation bar (immersive), не отображается в «Недавних» (`excludeFromRecents`), не позволяет уйти «назад» в целевое приложение (Back → Home).
  - **FR-51.** Содержимое: имя/иконка профиля, крупный оставшийся таймер сессии, мотивационная цитата (набор из ≥ 50 локализованных фраз, случайная, обновляется не чаще 1 раза в минуту), название приложения, которое пытались открыть, счётчик попыток за сессию («Это 4-я попытка»), кнопки согласно режиму, мелкая ссылка «Открыть Focus».
  - **FR-52.** Появление с анимацией fade+scale ≤ 200 мс; экран должен быть виден **до** того, как целевое приложение успеет отрисовать контент (см. TR-03).
  - **FR-53.** Тема: следует системной (light/dark), поддерживает динамический цвет (Material You). Опция «спокойный фон» (градиент/однотонный) и «пользовательский текст цели» (например «Диплом до пятницы»).
  - **FR-54.** Пользовательский текст цели задаётся при старте сессии (необязательно) и показывается крупно на экране блокировки.
  - **FR-55.** Экран блокировки корректно работает при повороте, в split-screen (перекрывает свою половину и переводит на Home), в режиме Picture-in-Picture целевого приложения (PiP закрывается через `GLOBAL_ACTION_HOME` + повторный показ).
  
  ### 4.7. Белый список (Allowlist)
  
  - **FR-60.** Неблокируемые всегда: сам Focus, текущий лаунчер по умолчанию, `com.android.systemui`, звонилка по умолчанию (`TelecomManager.getDefaultDialerPackage()`), экстренные вызовы, InCallUI, `com.android.phone`, клавиатура (IME) по умолчанию, `com.android.permissioncontroller`, `com.google.android.permissioncontroller`, Android Auto (`com.google.android.projection.gearhead`) при подключении к авто.
  - **FR-61.** Пользовательский белый список: список приложений, которые исключаются из любых профилей (например, «Карты», «Банк»). Редактируется вне сессии.
  
  ### 4.8. Расписания
  
  - **FR-40.** Расписание: профиль + дни недели + время начала + время окончания (может переходить через полночь) + флаг «включено». Неограниченное число расписаний; при пересечении применяется более строгий режим (hard > soft), список приложений объединяется.
  - **FR-41.** Запуск по расписанию — через `AlarmManager.setExactAndAllowWhileIdle` (или `setAlarmClock` при недоступности точных будильников с объяснением пользователю). После срабатывания — foreground service стартует сессию. Пропущенные срабатывания (устройство выключено) обрабатываются при загрузке: если «сейчас» внутри интервала — сессия стартует с оставшимся временем.
  - **FR-42.** За 5 минут до старта расписания hard lock — предупреждающее уведомление с кнопкой «Пропустить сегодня» (доступно, если в расписании включена опция «разрешить пропуск дня», по умолчанию — выключено).
  - **FR-43.** Все запланированные будильники пересоздаются при `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED`, `MY_PACKAGE_REPLACED`.
  
  ### 4.9. Статистика
  
  - **FR-80.** Экран «Статистика»: сегодня / 7 дней / 30 дней. Метрики: количество сессий, суммарное время фокуса, попытки открыть целевые приложения (всего и по приложениям, top-5), пропуски, процент завершённых сессий, streak (дней подряд ≥ 1 завершённая сессия), лучший streak.
  - **FR-81.** Графики (столбчатые/линейные) на Compose Canvas или библиотеке Vico. Без сети.
  - **FR-82.** Журнал событий (лог): время, тип (`SESSION_STARTED`, `BLOCK_SHOWN`, `BYPASS_GRANTED`, `SESSION_COMPLETED`…), приложение, причина пропуска. Хранится 90 дней, старое удаляется `WorkManager`-задачей раз в сутки.
  - **FR-83.** Экспорт статистики в CSV в папку, выбранную пользователем (`ACTION_CREATE_DOCUMENT`). Импорт — вне рамок.
  
  ### 4.10. Настройки
  
  - **FR-90.** Разделы: Разрешения (чек-лист FR-02), Внешний вид (тема, динамический цвет, язык через per-app language `LocaleManager`), Блокировка (тексты, цитаты, звук/вибрация при показе блокировки), Белый список, Данные (экспорт CSV, очистка статистики, удаление всех данных), О приложении (версия, лицензии OSS, политика конфиденциальности, «Как работает защита»).
  - **FR-91.** Настройки доступны во время сессии, кроме разделов, влияющих на блокировку (в hard lock: белый список, разрешения-отключение, удаление данных заблокированы с пояснением).
  
  ### 4.11. Виджеты, тайлы, ярлыки
  
  - **FR-70.** Виджет рабочего стола (Jetpack Glance): состояние (нет сессии / идёт / перерыв), таймер, кнопка «Старт» (последний профиль, длительность по умолчанию) / «Открыть». Размеры 2×1, 2×2, 4×2.
  - **FR-71.** Плитка быстрых настроек (`TileService`): состояние + запуск/остановка сессии последнего профиля (остановка недоступна в hard lock). При нажатии на неразрешённые обязательные разрешения — открывает Focus.
  - **FR-72.** Статические и динамические App Shortcuts: «Старт: <профиль>» для 3 последних профилей.
  
  ### 4.12. Локализация и доступность
  
  - **FR-100.** Языки v1.0: русский (основной), английский. Все строки в ресурсах; plural forms через `plurals`. Форматы времени/дат через `java.time` + `DateTimeFormatter` с локалью.
  - **FR-101.** Доступность: `contentDescription` для всех иконок, поддержка TalkBack на экране блокировки, минимальный размер касания 48dp, контраст ≥ 4.5:1, поддержка увеличенного шрифта до 200% без обрезания.

  ## 5. Нефункциональные требования
  
  - **NFR-01. Латентность блокировки:** p95 ≤ 300 мс от `ACTIVITY_RESUMED` целевого приложения до отображения экрана блокировки при активном Accessibility; ≤ 1000 мс в режиме polling.
  - **NFR-02. Батарея:** потребление в режиме активной сессии ≤ 2 % заряда за 8 часов на референс-устройстве (Pixel 6a / Android 14) при активном Accessibility; polling-режим ≤ 4 %.
  - **NFR-03. Память:** foreground service ≤ 40 МБ RSS в стабильном состоянии.
  - **NFR-04. Устойчивость:** сессия восстанавливается после перезагрузки, kill процесса, обновления приложения, смены времени/часового пояса.
  - **NFR-05. Размер APK:** ≤ 8 МБ (release, R8, ресурсы только ru/en, векторные иконки).
  - **NFR-06. Холодный старт главного экрана:** ≤ 800 мс на референс-устройстве; использовать Baseline Profiles.
  - **NFR-07. Адаптивность:** корректная работа в портрете/ландшафте, на экранах 320–1000 dp ширины (базовое поведение через `WindowSizeClass`), edge-to-edge (обязательно для targetSdk 36).
  - **NFR-08. Совместимость:** Android 8.0–16 (API 26–36), вендорские прошивки: Samsung One UI, Xiaomi HyperOS/MIUI, Huawei EMUI (без GMS — приложение не должно зависеть от GMS), OnePlus, Pixel.
  - **NFR-09. Качество кода:** покрытие unit-тестами доменного и data-слоёв ≥ 80 %; 0 предупреждений detekt/lint уровня error; предупреждения — не более 20 в baseline.
  - **NFR-10. Приватность:** без разрешения `INTERNET`; без сторонних SDK аналитики/крашей; данные не покидают устройство, кроме явного экспорта пользователем. Политика конфиденциальности — локальный HTML/текст.
  - **NFR-11. Безопасность данных:** БД в защищённом хранилище приложения; состояние активной сессии дублируется в Device Protected Storage (для Direct Boot). Шифрование БД (SQLCipher) — не требуется в v1.0.
  - **NFR-12. Соответствие Google Play:** декларация использования Accessibility API (форма «Accessibility service disclosure» + in-app prominent disclosure перед переходом в настройки), декларация `QUERY_ALL_PACKAGES` (core-функциональность — блокировка приложений), Foreground Service type `specialUse` с описанием, Data safety form: «данные не собираются».

  Единственный источник правды по версиям — `gradle/libs.versions.toml`. Раздел §6 дублирует его для чтения без открытия Gradle-файлов.

  ### 6.1. Политика версий (LOCKED)

  **Все версии из §6.2–§6.5 зафиксированы на весь срок разработки Focus v1.0 (до релиза 1.0.0 включительно).**

  - **Запрещено** повышать/понижать версии Gradle, AGP, Kotlin, KSP, BOM, AndroidX и любых сторонних библиотек «для актуальности», «по совету lint» или «потому что вышла новая stable».
  - **Запрещено** подключать альтернативные артефакты с другими координатами/версиями вместо перечисленных в catalog (в т.ч. захардкоженные строки `implementation("group:artifact:version")` в модулях).
  - **Разрешено** только: (a) добавить *новую* зависимость, которой ещё нет в §6, — через ADR в `docs/DECISIONS.md` с обновлением §6 и `libs.versions.toml`; (b) исправить опечатку в catalog, если она ломает сборку и не меняет задуманную версию.
  - Compose-артефакты **без явной версии** в catalog (`ui`, `material3`, `foundation` и т.д.) управляются **только** через `compose-bom` — отдельно их версии не задаются и не меняются.
  - Kotlin **2.4.x** и KSP под него **не использовать**: последний стабильный KSP — **2.3.11**, связка **Kotlin 2.3.21 + KSP 2.3.11** обязательна.

  ## 7. Архитектура
  
  ### 7.1. Принципы
  - **Clean Architecture + MVI/UDF** (unidirectional data flow) в UI: `ViewModel` держит `StateFlow<UiState>`, принимает `UiEvent`, эмитит одноразовые `UiEffect` через `Channel`.
  - Слои: `presentation (feature) → domain (use cases, models, repositories-interfaces) → data (Room, DataStore, system APIs)`. Domain — чистый Kotlin JVM-модуль без Android-зависимостей.
  - Системные API (UsageStats, Accessibility, WindowManager, AlarmManager, PackageManager) инкапсулируются за интерфейсами в `core:system` — для тестируемости и подмены.
  
  ### 7.2. Модульная структура (Gradle)
  
  ```

  ├── core/
  │   ├── common/                        # Result, dispatchers, extensions, Clock-абстракция

  │   ├── datastore/                     # Proto DataStore: настройки, ActiveSessionSnapshot
  ```

  ## 8. Ключевые технические решения (TR)
  
  ### TR-01. Детекция foreground-приложения (гибридная)
  
  **Основной канал — `AccessibilityService`:**
  - `accessibilityEventTypes = typeWindowStateChanged|typeWindowsChanged`, `accessibilityFlags = flagIncludeNotImportantViews|flagReportViewIds|flagRetrieveInteractiveWindows`, `canRetrieveWindowContent = false` (не читаем содержимое — минимизация данных), `canPerformGestures = false`, `notificationTimeout = 50`.
  - В `onAccessibilityEvent` берём `event.packageName` и `event.className`; фильтруем IME, всплывающие окна (`TYPE_WINDOW_STATE_CHANGED` с классом диалогов, тостов), собственный пакет. Дополнительно валидируем через `rootInActiveWindow?.packageName` и `windows` (активное окно с `type == TYPE_APPLICATION`).
  - Сервис — тонкий: только преобразует события в `ForegroundAppEvent(packageName, className, timestamp)` и публикует их в синглтон `ForegroundEventBus` (`MutableSharedFlow`, `extraBufferCapacity = 64`, `DROP_OLDEST`). Никакой бизнес-логики внутри сервиса.
  - Предоставляет действия `goHome()` / `goBack()` через `performGlobalAction`.
  - Обязательный **prominent disclosure** (диалог) перед переходом в настройки Accessibility (требование Google Play).
  
  **Резервный канал — `UsageStatsManager`:**
  - При отсутствии Accessibility. Поллинг в корутине сервиса: `queryEvents(now - 2000, now)`, обработка `ACTIVITY_RESUMED` (API 29+) / `MOVE_TO_FOREGROUND` (API 26–28), последнее событие = foreground. Интервал адаптивный: 500 мс первые 5 с после включения экрана/выхода из целевого приложения, затем 1000 мс; при выключенном экране (`ACTION_SCREEN_OFF`) поллинг приостанавливается; при `ACTION_USER_PRESENT` — возобновляется с 300 мс на 3 с.
  - Кеширование результата: не эмитить событие, если пакет не изменился.
  
  **Оркестрация:** `DetectorOrchestrator` слушает состояние разрешений (`PermissionStateFlow`) и переключает источник на лету. При активном Accessibility polling выключен полностью (батарея).
  
  ### TR-02. Показ экрана блокировки
  
  **Основной способ — `BlockActivity`:**
  - `launchMode="singleInstance"`, `taskAffinity=""`, `excludeFromRecents="true"`, `noHistory="true"`, `showWhenLocked="true"`, `turnScreenOn="false"`, `theme` — прозрачный старт без splash, `configChanges` покрывают orientation/screenSize/uiMode (чтобы не пересоздавать при повороте).
  - Запуск из сервиса: `startActivity(intent.addFlags(FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_CLEAR_TASK or FLAG_ACTIVITY_NO_ANIMATION))`. Запуск активности из фона на Android 10+ разрешён, т. к. у приложения есть `SYSTEM_ALERT_WINDOW` (документированное исключение) **и/или** активный foreground service, стартовавший до этого. Проверка: `PermissionChecker.canDrawOverlays()`.
  - `onBackPressedDispatcher` → `goHome()` (через Accessibility или `Intent(ACTION_MAIN).addCategory(CATEGORY_HOME)`), затем `finish()`.
  - В `onPause`/`onStop`, если сессия ещё активна и целевое приложение опять на переднем плане → повторный показ (защита от «смахивания»). Anti-loop: не более 1 показа в 400 мс на пакет.
  - Immersive mode через `WindowInsetsControllerCompat.hide(systemBars())` + `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`.
  
  **Резервный способ — оверлей через `WindowManager`:**
  - Используется, если `startActivity` не привёл к `onResume` `BlockActivity` за 600 мс (например, вендорские ограничения) — фиксируется через `ActivityLifecycleCallbacks`.
  - `WindowManager.LayoutParams(TYPE_APPLICATION_OVERLAY)`, `MATCH_PARENT × MATCH_PARENT`, flags: `FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS | FLAG_SHOW_WHEN_LOCKED | FLAG_HARDWARE_ACCELERATED`, `layoutInDisplayCutoutMode = SHORT_EDGES`, `fitInsetsTypes = 0`, фокусируемый (без `FLAG_NOT_FOCUSABLE`), чтобы перехватывать Back через `dispatchKeyEvent` в корневом `FrameLayout`.
  - Контент — `ComposeView`; для него вручную устанавливаются `ViewTreeLifecycleOwner`, `ViewTreeSavedStateRegistryOwner`, `ViewTreeViewModelStoreOwner` через собственный `OverlayLifecycleOwner` (LifecycleRegistry). Переиспользуется тот же `BlockScreen` composable, что и в `BlockActivity`.
  - Известное ограничение: приложения с `HIDE_OVERLAY_WINDOWS` (Android 12+) могут скрывать такие оверлеи — поэтому оверлей только резервный, а не основной.
  
  **Единый UI:** `feature:blocker` экспортирует `@Composable fun BlockScreen(state: BlockUiState, onAction: (BlockAction) -> Unit)`; и Activity, и overlay используют его.
  
  ### TR-03. Скорость реакции
  - Сервис уже запущен и держит в памяти `Set<String>` целевых пакетов активной сессии (обновляется по `Flow` из БД). Решение о блокировке — O(1) без обращения к БД.
  - `BlockActivity` предварительно «прогрет»: тема без splash, минимальный `onCreate`, `setContent` с уже подготовленным state (передаётся через `Intent extras` + `StateFlow` сервиса).
  - Метрика `detect→shown` пишется в лог (`BLOCK_LATENCY_MS`) и отображается в скрытом экране диагностики (`Настройки → О приложении → 7 тапов по версии`).
  
  ### TR-04. Foreground service и жизненный цикл
  - `FocusForegroundService`: `android:foregroundServiceType="specialUse"`, `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" android:value="Blocks user-selected apps during focus sessions by monitoring foreground app"/>`, permission `FOREGROUND_SERVICE_SPECIAL_USE` + `FOREGROUND_SERVICE`.
  - Старт: `ContextCompat.startForegroundService` + `startForeground()` в первые 5 с (в `onCreate`). `START_STICKY`. При `onTaskRemoved` — ничего не делать (сервис независим от UI-таска).
  - Сервис живёт **только** пока есть активная сессия или запланированная в ближайшие 60 с. Иначе `stopSelf()` — экономия батареи. Уведомление — канал `session` (IMPORTANCE_LOW, без звука), `setOngoing(true)`, `setOnlyAlertOnce(true)`.
  - На Android 14+ учитывать таймауты FGS (для `specialUse` их нет, но `dataSync` не использовать).
  - Запросить `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` с объяснением. Для Xiaomi/Huawei/Samsung — экран подсказок «Автозапуск / Не оптимизировать» с deep links на вендорские экраны (список интентов с graceful fallback).
  
  ### TR-05. Персистентность сессии и восстановление
  - Активная сессия хранится в Room (`sessions`, `status=RUNNING`) **и** дублируется как `ActiveSessionSnapshot` в Proto DataStore в **device-protected storage** (`context.createDeviceProtectedStorageContext()`), чтобы `LOCKED_BOOT_COMPLETED` мог восстановить сессию до разблокировки телефона.
  - Конец сессии — `AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP, endAt, pendingIntent)` + внутренняя корутина-таймер (двойная гарантия). При ошибке точных будильников — `setWindow` с окном 60 с.
  - `BootReceiver` (`BOOT_COMPLETED`, `LOCKED_BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `TIME_SET`, `TIMEZONE_CHANGED`) → `RestoreSessionUseCase`: если снимок есть и `endAt > now` — стартовать сервис; иначе завершить сессию как `EXPIRED` и пересоздать будильники расписаний.
  
  ### TR-06. Логика решения о блокировке (`BlockDecisionEngine`)
  Вход: `ForegroundAppEvent`, состояние сессии, allowlist, активные окна доступа, флаги (screen on/off, in-call).
  Правила по приоритету:
  1. Нет `RUNNING` сессии или идёт перерыв помодоро → `Allow`.
  2. Пакет в системном/пользовательском allowlist → `Allow`.
  3. Активный телефонный звонок (`TelephonyCallback`/`PhoneStateListener`) и пакет — звонилка → `Allow`.
  4. Активное окно доступа для пакета → `Allow` (с планированием повторной проверки на его конце).
  5. Пакет ∈ targets(сессии) ∪ hardLockExtras (если hard) → `Block(reason)`.
  6. Иначе `Allow`.
  Движок — чистый Kotlin в `core:domain`, покрыт unit-тестами на таблицу случаев.
  
  ### TR-07. Soft lock — процедура пропуска
  - `BypassFlow` реализован как конечный автомат в `feature:blocker`: `Idle → Delay(remaining) → Breathing(cycle) → Reason(text) → Phrase(text) → Granted(accessWindowEndAt) | Denied(limitReached)`. Порядок шагов — из настроек профиля.
  - Уход с экрана блокировки во время процедуры → сброс в `Idle`.
  - `Granted` → `AccessWindowRepository.grant(packageName, until)` → сервис перестаёт блокировать пакет; `AlarmManager`/таймер на `until` → повторная проверка foreground и показ блокировки при необходимости.
  - Ввод текста — `TextField` с `keyboardOptions(autoCorrect=false)`, запрет вставки (перехват `onValueChange` — если длина выросла > 1 символа за раз при отсутствии IME-композиции → отклонить).
  
  ### TR-08. Hard lock — защита (Tamper protection)
  - Расширение targets: `SettingsPackagesResolver` собирает пакеты для `Settings.ACTION_SETTINGS`, `ACTION_ACCESSIBILITY_SETTINGS`, `ACTION_APPLICATION_DETAILS_SETTINGS`, `ACTION_MANAGE_OVERLAY_PERMISSION`, `ACTION_USAGE_ACCESS_SETTINGS` (все `resolveActivity` результаты), плюс список installer/market пакетов.
  - Разрешённые ярлыки настроек (FR-36): Focus запускает `Settings.ACTION_WIFI_SETTINGS` и т. п., регистрируя `AccessWindow(settingsPkg, 60 с, restrictedToActivity=className)`. Если детектор видит в Settings `className`, отличный от разрешённого (например, экран «Специальные возможности»), — блокировка немедленно.
  - Через Accessibility при попадании в Settings → `GLOBAL_ACTION_BACK` затем `GLOBAL_ACTION_HOME`, потом показ `BlockScreen`.
  - Device Admin: `FocusDeviceAdminReceiver` без политик (`<uses-policies/>` пустой) — только для защиты от удаления. Активация через `DevicePolicyManager.ACTION_ADD_DEVICE_ADMIN` с объяснением. `onDisableRequested` возвращает текст-предупреждение. Автоматическая деактивация по окончании сессии — если пользователь так настроил.
  - Смена лаунчера: при старте hard-сессии сохраняется текущий дефолтный лаунчер; остальные лаунчеры добавляются в блок.
  - **Честность:** экран «Как работает защита» описывает, что обходится (safe mode, ADB, factory reset).
  
  ### TR-09. Список приложений
  - `PackageRepository` через `PackageManager.queryIntentActivities(Intent(ACTION_MAIN).addCategory(CATEGORY_LAUNCHER), MATCH_ALL)`; `QUERY_ALL_PACKAGES` объявлен (обоснование для Play: основная функция — блокировка любых приложений). Кеш в памяти + `PackageChangeReceiver` (`PACKAGE_ADDED/REMOVED/CHANGED/REPLACED`) для инвалидации.
  - Иконки — через Coil с кастомным `Fetcher` (`PackageManager.getApplicationIcon`), ключ `pkg:versionCode`, memory+disk cache.
  - Время использования за 7 дней — `UsageStatsManager.queryAndAggregateUsageStats`.
  
  ### TR-10. Расписания
  - `ScheduleAlarmPlanner`: для каждого включённого расписания рассчитывает ближайшие `startAt`/`endAt` (с учётом перехода через полночь и DST через `ZonedDateTime`), регистрирует `PendingIntent` с уникальным `requestCode = hash(scheduleId, type)`. Перепланирование при любом изменении.
  - При `AlarmManager.canScheduleExactAlarms() == false` (Android 12+) — экран объяснения + fallback `setWindow(…, 60_000)`.
  
  ### TR-11. Уведомления
  - Каналы: `session` (LOW), `alerts` (DEFAULT — предупреждения перед началом hard lock, конец окна доступа), `summary` (DEFAULT — итоги сессии). `POST_NOTIFICATIONS` запрашивается на экране разрешений.
  
  ### TR-12. Edge-to-edge, темы, дизайн-система
  - `enableEdgeToEdge()` в каждой Activity; `Scaffold` с корректными insets. Динамический цвет (`dynamicColorScheme`) при API 31+, fallback — собственная палитра (primary: спокойный сине-зелёный `#2F6F6D`, tertiary: тёплый янтарь). Типографика — Roboto/Google Sans (системный), шкала M3. Компоненты дизайн-системы: `FocusButton`, `FocusCard`, `TimerDial` (кольцо прогресса), `AppIconRow`, `PermissionRow`, `StatChip`.
  
  ### TR-13. Обработка ошибок и диагностика
  - Все системные вызовы — обёрнуты в `runCatching` с логированием через Timber. В release Timber пишет в кольцевой файл (`filesDir/logs/focus.log`, 1 МБ) — экспорт по кнопке «Поделиться диагностикой» (файл отправляется через `ACTION_SEND`, только по действию пользователя).
  - Глобальный `Thread.UncaughtExceptionHandler` записывает стек в файл; при следующем запуске предлагает отправить/скопировать.

  ```kotlin
  data class EventLogEntity(
      @PrimaryKey(autoGenerate = true) val id: Long = 0,
      val timestamp: Long, val sessionId: String?, val type: String,
      // SESSION_STARTED, SESSION_PAUSED, SESSION_RESUMED, SESSION_COMPLETED, SESSION_CANCELLED, SESSION_EXPIRED,
      // BLOCK_SHOWN, BYPASS_STARTED, BYPASS_GRANTED, BYPASS_DENIED, ACCESS_WINDOW_EXPIRED,

  )

  data class AllowlistEntity(@PrimaryKey val packageName: String, val addedAt: Long)
  ```

  ## 10. Конечный автомат сессии (`SessionStateMachine`, чистый Kotlin)
  
  | Состояние | Событие | Новое состояние | Побочные эффекты |
  |---|---|---|---|
  | `Idle` | `Start(profile, duration, goal)` | `Running` | insert session, snapshot, alarm(end), start FGS, notification, log |
  | `Running` | `Tick` | `Running` | обновить notification (раз/мин) |
  | `Running` | `Pause` (soft, лимит не исчерпан) | `Paused(until)` | alarm(resume), notification |
  | `Paused` | `Resume` / alarm | `Running` | |
  | `Running` | `EndAlarm` / `now ≥ plannedEndAt` | `Completed` | stats, summary notification, stop FGS, device admin off (если настроено) |
  | `Running` | `StopRequested` (soft) | `Cancelled` | подтверждение в UI |
  | `Running` (hard) | `EmergencyExitRequested` | `Running(exitPendingUntil)` | alarm(10 мин) или экран перепечатки |
  | `Running(exitPending)` | `EmergencyExitConfirmed` | `Cancelled` | |
  | `Running` | `Restore(snapshot)` при boot, `endAt ≤ now` | `Expired` | |
  | `Running` (pomodoro) | `PhaseEnd` | `Running(phase=Break)` / `Running(phase=Focus)` | notification, block on/off |
  
  Инварианты (проверяются тестами): не более одной `RUNNING/PAUSED`; в `HARD` невозможны `Pause` и `StopRequested`; `bypassesUsed ≤ limit`.

  ### 11.2. Экраны (краткая спецификация)
  - **Home:** большая карточка статуса (нет сессии → «Начать фокус»; идёт → кольцо-таймер, профиль, попытки, кнопки «Пауза»/«Завершить» по режиму); ряд «Быстрый старт» с последними профилями; предупреждающий баннер, если разрешения потеряны; карточка «Сегодня: X мин фокуса, streak N».
  - **StartSession:** выбор профиля (chips), длительность (сегментированные пресеты + слайдер + «до времени»), текст цели, переключатель «Помодоро» с параметрами, кнопка «Старт» (в hard lock — вторая ступень подтверждения с описанием последствий и слайдером-подтверждением «Проведите, чтобы включить hard lock»).
  - **ActiveSession:** полноэкранный таймер, список целевых приложений, кол-во попыток, пропуски (осталось), кнопки согласно режиму.
  - **BlockScreen:** см. FR-50–55.
  - **ProfileEditor:** имя, эмодзи/цвет, приложения (превью иконок + «Изменить»), режим (segmented Soft/Hard) с раскрывающимися настройками, длительность по умолчанию.
  - **AppPicker:** поиск, сортировка, список с чекбоксами, sticky-счётчик выбранных, кнопка «Готово».
  - **Permissions:** список `PermissionRow` (иконка, название, статус-чип, описание, кнопка «Настроить»), внизу «Всё готово» когда обязательные получены.
  - **Schedules:** список карточек (дни, время, профиль, режим, toggle); редактор — day-chips, time pickers, профиль.
  - **Stats:** переключатель периода, 3–4 KPI-карточки, график по дням, top-5 приложений, кнопка «Журнал».
  - **Settings/About:** стандартные списки M3.
  
  ### 11.3. Состояния UI
  Каждый экран обрабатывает: `Loading`, `Empty` (иллюстрация + CTA), `Error` (с retry), `Content`. Skeleton/shimmer — не требуется, достаточно `CircularProgressIndicator` при > 300 мс.
  
  ### 11.4. Анимации
  `AnimatedContent` для смены статуса на Home, `animateFloatAsState` для кольца таймера, shared-element transitions между карточкой профиля и редактором (Compose `SharedTransitionLayout`) — желательно, не обязательно.

  1. Свежая установка → онбординг → все разрешения → первая сессия ≤ 2 мин.
  2. Soft lock: блокировка ≤ 300 мс; задержка/дыхание/причина/фраза; лимит; окно доступа; «Завершить».
  3. Hard lock: нет пропуска; Настройки/Play Store/App info заблокированы; Back → Home; Recents-смахивание — возвращается; перезагрузка — сессия жива; ADB kill — сервис восстановлен; аварийный выход по каждому режиму.
  4. Расписание: пересечение полночи; DST; отключение; «Пропустить сегодня».
  5. Помодоро: фазы, уведомления, разблокировка в перерыве.
  6. Виджет/тайл/ярлыки.
  7. Поворот, split-screen, PiP целевого приложения, входящий звонок во время блокировки.
  8. Отзыв разрешения во время сессии → баннер + уведомление `PERMISSION_LOST`, fallback детектор.
  9. Тёмная/светлая тема, ru/en, шрифт 200 %, TalkBack на BlockScreen.
  10. Статистика/экспорт CSV/очистка данных.

  ## 17. Риски и митигация
  
  | Риск | Вероятность | Влияние | Митигация |
  |---|---|---|---|
  | Google Play отклоняет использование Accessibility API | Средняя | Высокое | Prominent disclosure, честное описание, полноценный fallback на UsageStats (приложение работает и без Accessibility); подготовить видео-обоснование. |
  | Старт Activity из фона блокируется на конкретной прошивке/версии | Средняя | Высокое | Overlay-fallback (TR-02), диагностика, вендорские подсказки. |
  | Вендорские прошивки убивают FGS | Высокая | Среднее | Игнор оптимизации батареи, вендорские подсказки, `START_STICKY`, alarm-«пульс» каждые 15 мин, проверяющий живость сервиса, `WorkManager` периодический watchdog. |
  | Неверная детекция (IME, диалоги, split-screen) | Средняя | Среднее | Фильтры по типу окна, валидация через `windows`, тесты на фикстурах событий, диагностический экран. |
  | Пользователь блокирует себе критичные приложения (звонки) | Низкая | Высокое | Жёсткий системный allowlist, телефонный звонок всегда разрешён. |
  | Device Admin deprecated-предупреждения | Низкая | Низкое | Не используем политики, только защита от удаления; функция опциональна. |
  | Изменения в Android 16+ | Средняя | Среднее | Раздел 12.2, регрессионный чек-лист при каждом новом targetSdk. |
  | Латентность polling-режима > 1 с на слабых устройствах | Средняя | Среднее | Адаптивный интервал, приоритет Accessibility в онбординге. |
